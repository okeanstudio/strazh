# Сквозное шифрование на нескольких устройствах

Устройства аккаунта имеют отдельные ключи. Для восстановления истории после
входа паролем или SMS приложение получает резервную копию ключей из серверного
escrow. Записи доступны только авторизованному владельцу аккаунта через RLS,
но ключи в этой копии не зашифрованы клиентским паролем: администратор или
компрометация Supabase-сервера могут раскрыть историю.

Для совместимости остаётся и клиентская копия, зашифрованная ключом,
полученным из пароля аккаунта через PBKDF2-HMAC-SHA256 с уникальной солью.
При входе паролем приложение импортирует ключи из обеих копий, объединяет их и
обновляет резервные копии. При входе по SMS ключи восстанавливаются из
серверного escrow. Новые устройства добавляются в escrow после авторизации.

Старые парольные копии пользователей переносятся в escrow при следующем
успешном входе паролем. Если пользователь уже потерял все устройства и ни разу
не переносил ключи в escrow, восстановить историю по одному SMS нельзя.

Для установки:

1. Применить миграции
   `supabase/migrations/202611220001_chat_encryption_key_vault.sql` и
   `supabase/migrations/202611230003_chat_encryption_key_server_escrow.sql`
   к базе.
2. Развернуть обновлённый клиент.
3. С существующего устройства или через вход паролем перенести прежние ключи
   в escrow. После этого новые устройства смогут восстановить историю как по
   паролю, так и по SMS.

Сброс или изменение пароля должен использовать штатный сценарий смены пароля
приложения, чтобы повторно зашифровать контейнер. Если пароль утрачен и ни одно
устройство с доступными ключами не осталось, восстановить историю невозможно.
