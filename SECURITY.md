# Безопасность

## Сообщить об уязвимости

Пожалуйста, не публикуйте непатченые уязвимости, персональные данные или
действующие секреты в открытых issues и pull requests.

Если для репозитория доступна функция GitHub Private vulnerability reporting,
отправьте сообщение через неё. В противном случае свяжитесь с сопровождающими
через приватный канал и передайте только минимальные сведения, необходимые для
воспроизведения и исправления проблемы. Не прикладывайте данные реальных
пользователей.

## Эксплуатация

Перед использованием с реальными данными самостоятельно проверьте настройки
Supabase, Firebase, push-уведомлений и серверных функций. Не храните в клиенте
или Git ключи `service_role`, приватные ключи, пароли, токены или секреты
сервисных аккаунтов. Публичные клиентские ключи не заменяют проверки доступа:
включите и проверьте RLS и ограничения соответствующих сервисов.

Чаты используют облачную модель, а не E2E: сервер получает содержимое сообщений,
чтобы синхронизировать историю между устройствами. Защита зависит от HTTPS,
корректной конфигурации Supabase, RLS и прав доступа к Storage. Примените
миграцию `supabase/migrations/202611080002_cloud_chat_access.sql`; проверьте
политики и доступ к вложениям в используемой Supabase-инсталляции. Не
используйте облачные чаты, если сервер не должен иметь возможности обработать
содержимое.

Старый общий ключ удален; старые сообщения и резервные копии на сервере
автоматически не удаляются, а сообщения из экспериментальной E2E-версии могут
быть нечитаемы. Push-уведомления могут раскрывать факт нового сообщения и
идентификатор чата.

Перед публичной публикацией проверьте не только текущие файлы, но и всю Git
историю: удалённые из последнего коммита секреты остаются доступны в старых
коммитах. При обнаружении действующего секрета отзовите и замените его; одной
очистки истории недостаточно. Не публикуйте IPA и другие сборки вместе с
исходниками.

Сообщения об уязвимости не являются гарантией наличия исправления или
определённого срока ответа.
